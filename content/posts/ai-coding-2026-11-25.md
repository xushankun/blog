### 2. fast-anything：别把整个项目重写成 Rust——只重写慢的 5%
**类型**：开源工具 | **热度**：⭐⭐⭐⭐⭐
**链接**：[github.com/EL4CTEO/fast-anything](https://github.com/EL4CTEO/fast-anything)
**核心亮点**：
- 11 月 21 日发布，三天 3.6k Star，Trendshift 上榜；与上周 8k Star 的 rust-anything 同思路但更务实
- 一条命令流水线：`scan` 按「耗时 × 可移植性」排热点函数 → `port` 录制最多 500 次真实调用并生成单函数 Rust crate → `verify` 重放全部录制调用逐项比对（浮点误差 ≤1e-9、报错行为一致）→ `enable`/`disable` 一键切换、完全可逆
- 「Proof, not vibes」：实战中 500 次真实调用抓到一个「按字节而非字符比较」的移植错误；移植后比原实现还慢的 Rust 一律不启用
**适用场景**：Python / Node / Ruby / Java / Go 等应用的局部性能优化，想尝鲜 Rust 重写但不想付整体重写成本

## 🛠️ Agent 工具链

### 3. agy-fast：给 Antigravity 装上「省 token 加速器」
**类型**：开源工具 | **推荐指数**：⭐⭐⭐⭐
**链接**：[github.com/INK-Q/agy-fast](https://github.com/INK-Q/agy-fast)
**核心亮点**：
- 针对 Google Antigravity（CLI / Desktop / IDE）的本地 MCP 插件，零运行时依赖：官方基准 LLM 轮次 -33.7%、计费配额 -31.5%、工具返回上传流量 -39.7%
- 原理是「批处理 + 缓存」：把高频搜索、符号大纲、多文件原子编辑、构建/测试检查合并成本地批调用，每次会话注入一次 <50ms 的工作区快照
- 不改 Antigravity 原生 UI / diff / 检查点 / 安全检查，声明「policy-compliant」
**适用场景**：重度使用 Antigravity 且被 token 配额和响应延迟卡脖子的团队

### 4. skill-distill：把一次好会话蒸馏成开源模型能复现的 Skill
**类型**：Agent Skill | **推荐指数**：⭐⭐⭐⭐⭐
**链接**：[github.com/sybil-solutions/skill-distill](https://github.com/sybil-solutions/skill-distill)
**核心亮点**：
- 核心问题：「前沿模型把活干得漂亮，开源模型照着做行不行？」——它把 Claude Code / Codex 的一次好会话蒸馏成 Skill，交给指定的「学生」（某个 harness + 开源模型）复现
- 老师循环五步：读会话写 Skill → 在 tmux 里起学生、从原始状态重跑 → 对比参考结果 → 定位第一个出错点改 Skill → 每版跑三次直到达标；最终由人对照验收
- 产出两件东西：可复用的「蒸馏操作 Skill」本身 + 一个针对特定任务/模型/harness 的成品 Skill
**适用场景**：想把贵的前沿模型跑出来的最佳实践下放到便宜的本地/开源模型上，做团队知识沉淀

### 6. Genesis Map：给 Agent 的改动画一张「会坏在哪」地图
**类型**：开源工具 | **推荐指数**：⭐⭐⭐⭐
**链接**：[github.com/GenesisAgentInfra/genesis](https://github.com/GenesisAgentInfra/genesis)（[Show HN](https://news.ycombinator.com/item?id=50623965)）

## 🎯 本期 Prompt 技巧

### 「验证优先」移植与复现咒语
```markdown
# 让 AI 干活时先要证据，再要结果（fast-anything + skill-distill 的共同思想）

1. 先录基线：「动手前，先用真实输入记录原实现的行为快照（含边界用例）」
2. 小步替换：「每次只改一个函数/模块，改完立即回放快照比对，全部一致再继续」
3. 失败归因：「如果复现不通过，指出第一个偏离点在哪一步，只修那里，每版跑 3 次」
4. 可逆开关：「保留原实现，用开关切换新旧，随时回退」

# 示例
❌ 「把这个 API 用 Rust 重写，要求更快」
   → 一口气输出 2000 行，行为悄悄漂移，快没快不知道

✅ 「先录 500 组真实调用的响应 → 只移植最热的 3 个函数 →
    逐组回放比对（浮点误差 ≤1e-9、报错行为一致）→ 比原实现慢就别启用」
   → 每一步都有数字，好不好用数据说了算
```
